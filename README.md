## 四个时间视角

| 视角 | 适合安排             |
| ---- | -------------------- |
| 今天 | 选出眼下最重要的一步 |
| 三天 | 留出近期行动的余地   |
| 本周 | 记录阶段成果与下一步 |
| 本月 | 看清更长线的方向     |

计划可以在四个视角之间移动。周计划和月计划也能拆成今天可以开始的行动。

## 功能

- **轻量看板：** 新建、编辑、完成和移动计划；支持备注、日期调整、拖放与键盘操作。
- **今日重点：** 每天标记一项优先计划，帮助把注意力放在最重要的事情上。
- **持久计划：** 设置每日目标和持续日期，逐日生成独立任务；恢复立即生效并补齐当日任务，修改、暂停和停止从次日生效，历史记录会保留。
- **待重新安排与回收站：** 过期未完成的普通计划不会自动顺延；可手动改期，误删内容可恢复。
- **完成统计：** 查看完成率与连续完成天数；按日、周或累计总量浏览活动热力图，也可以查看历史年份。
- **轻柔动效：** 统计热力图会以边框波纹提示日期活动；图标、卡片和主题切换也有响应动效，并遵循系统的减少动态效果设置。
- **个人设置：** 浅色与深色主题、每日鼓励语，以及当前运行环境的资源用量。

## 快速开始

### 环境要求

- Node.js 22.12 或更高版本
- pnpm 12.3.4
- Go 1.27 或更高版本

### 启动开发环境

在项目根目录运行：

```sh
pnpm install
pnpm dev
```

打开 [http://127.0.0.1:5178](http://127.0.0.1:5178)。首次使用时创建个人账号，之后使用同一账号登录。项目没有预置账号或默认密码。

开发模式会构建并启动 Go API 与 Vite。修改前端会自动刷新；修改 Go 代码后重新运行 `pnpm dev`。按 Ctrl+C 可同时停止开发服务。

### 在手机或其他电脑上试用

确保设备连接到同一 Wi-Fi，在项目根目录启动：

```sh
HOST=0.0.0.0 pnpm dev
```

然后在另一台设备打开运行电脑的局域网 IP 加端口，例如 `http://192.168.1.10:5178`。这是用于可信局域网的开发测试方式，请勿直接暴露到公网。

## 常用命令

| 命令                     | 说明                                        |
| ------------------------ | ------------------------------------------- |
| `pnpm dev`               | 启动开发 API 和 Vite，前端修改后自动刷新    |
| `pnpm check`             | 检查 TypeScript 并运行 Go vet               |
| `pnpm test`              | 运行前端状态和 Go 测试                      |
| `pnpm build`             | 构建前端和 Go 服务                          |
| `pnpm start`             | 启动构建后的本地服务                        |
| `pnpm test:cloudflare`   | 在 Workers 运行时验证云端接口与 D1 数据行为 |
| `pnpm deploy:cloudflare` | 构建前端、应用 D1 迁移并部署 Worker         |

运行 `pnpm start` 前先执行 `pnpm build`，然后打开 [http://127.0.0.1:8788](http://127.0.0.1:8788)。

## 配置与数据

可将 `.env.example` 复制为 `.env`。不配置时，服务仅监听本机地址，使用项目目录中的默认数据库。

| 变量            | 默认值           | 用途                                                  |
| --------------- | ---------------- | ----------------------------------------------------- |
| `HOST`          | `127.0.0.1`      | 服务监听地址；局域网开发时可设为 `0.0.0.0`            |
| `DATA_PATH`     | `.data/plans.db` | SQLite 数据库文件路径                                 |
| `PORT`          | `8788`           | `pnpm start` 使用的服务端口；开发 API 固定使用 `8788` |
| `COOKIE_SECURE` | `false`          | 通过 HTTPS 提供服务时设为 `true`                      |

账号、计划和每日语录缓存保存在 SQLite 中。可从界面导出 JSON 备份。不要提交 `.env`、`.data` 或包含个人计划的导出文件。

多设备访问同一份数据时，需要连接同一个后端。云端版本使用 Cloudflare D1；分别在多台电脑启动本地服务会使用各自的 SQLite 数据库。本地和云端数据独立，不会自动迁移或合并。

每日鼓励语只请求固定的「鼓励」分类，不会上传用户名、计划内容或完成记录；请求失败时使用内置文案。

## 技术栈

- 前端：React、TypeScript、Vite、Motion、Three.js
- 本地后端：Go、Gin、SQLite
- 云端后端：Cloudflare Workers、TypeScript、D1

## 部署说明

访问地址：[四格计划](https://four-plans.zhangluck598.workers.dev)。云端首次使用需要初始化密钥，由空间所有者创建账号；之后只允许该账号登录，没有开放注册。账号、计划、完成记录和语录缓存保存在 D1，重新部署不会清空数据库。

推送到 `main` 会触发 [Cloudflare 工作流](https://github.com/518luck/four-plans/actions/workflows/cloudflare.yml)：先检查类型、运行 Go 与 Workers/D1 测试、构建前端，再应用新增迁移、发布并验证公网服务。Pull Request 只执行检查；也可手动运行工作流。修改本地文件后需要提交并推送到 GitHub，才会触发部署。

配置和首次部署步骤见 [Cloudflare 部署文档](docs/CLOUDFLARE.md)。令牌只保存在 GitHub Actions Secret；账号 ID 和数据库 ID 不是凭据。不要提交部署令牌、初始化密钥或个人数据。

资源面板在本地显示 Go 已分配堆与 SQLite 文件占用，云端显示实际 D1 存储。Workers 不提供进程已用内存读数，因此显示「暂不可读取」及运行上限，不把上限当成实际用量。
